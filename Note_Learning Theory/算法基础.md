# Sparsh、MAE、DINO、I-JEPA、V-JEPA 对比

## 1. 先看最核心的区别

| 方法 | 输入数据 | 模型在做什么 | 预测目标 / 学习信号 | 主要学习偏好 |
|---|---|---|---|---|
| **MAE** | 单张图像 | 用可见 patch 重建被遮挡 patch | 原始像素（pixel reconstruction） | 细节、纹理、局部结构 |
| **DINO** | 同一图像的多个增强 view | 让 student 匹配 teacher 对同一图像的表示 | teacher 的概率分布 / embedding（self-distillation） | 对数据增强不变的语义 |
| **I-JEPA** | 单张图像 | 用可见 context 预测被遮挡 target block 的表示 | 目标区域的潜在表示（latent prediction） | 高层语义和空间结构 |
| **V-JEPA** | 视频 / 多帧序列 | 用可见时空 context 预测被遮挡时空区域的表示 | 目标时空区域的潜在表示 | 外观 + 运动 + 时间变化 |
| **Sparsh** | 视觉式触觉图像 / 短时间窗 | 将 MAE、DINO/DINOv2、I-JEPA 等 SSL 方法适配到触觉数据 | 取决于 Sparsh 的具体变体 | 跨任务、跨传感器的通用触觉表示 |

> [!important] 先纠正一个分类问题
> **MAE、DINO、I-JEPA 和 V-JEPA 是不同的自监督学习方法；Sparsh 是一组面向触觉的基础模型。**
>
> Sparsh 没有只定义一种全新的 loss，而是在触觉数据上研究了 MAE、DINO/DINOv2 和 JEPA 等路线。所以更准确的对比是：
>
> $$
> \text{Sparsh}=触觉领域+大规模自监督预训练+多种 SSL 目标
> $$

## 2. 统一分析框架：它们到底在“预测什么”？

理解这些方法时，不要只记模型名字，而要连续问五个问题：

1. **输入是什么？** 单张图像、不同 view，还是一段时序？
2. **什么信息被隐藏或扰动？** 随机 patch、大块区域，还是时空 tube？
3. **预测什么？** 像素、teacher 输出，还是 target embedding？
4. **目标由谁产生？** 原始输入、momentum teacher，还是 target encoder？
5. **什么信息会被迫保留？** 低层细节、语义不变性，还是对未知区域的可预测结构？

最核心的分叉是：

```text
输入空间预测：MAE      context → pixels
表示对齐：    DINO     view 1  ↔ view 2
潜在空间预测：I-JEPA   context → image-region embedding
时空潜在预测：V-JEPA   context → video-region embedding
触觉领域适配：Sparsh    tactile data + 上述多种目标
```

## 3. MAE：重建“看不见的像素”

### 3.1 训练过程

MAE（Masked Autoencoder）先遮住大量图像 patch，encoder 只处理剩余的可见 patch，轻量 decoder 再尝试恢复被遮住区域的像素。

$$
\hat{x}_{\text{masked}}=D\left(E(x_{\text{visible}})\right)
$$

$$
\mathcal{L}_{\text{MAE}}
=\left\|\hat{x}_{\text{masked}}-x_{\text{masked}}\right\|_2^2
$$

> “根据我看到的部分，被挡住的地方**具体长什么样**？”

### 3.2 它倾向学到什么？

因为 loss 直接计算在像素空间，模型需要保留颜色、纹理、边缘和局部形状等信息。它也能学到语义，但预训练目标本身要求它解释很多下游任务未必需要的低层细节。

### 3.3 优势与限制

- **优势**：结构简单、训练稳定；高遮挡率使 encoder 计算高效；对密集、细节敏感任务有吸引力。
- **限制**：像素精确重建可能将容量浪费在背景、光照或传感器外观上；不会显式要求表示对不同 view 保持不变。

## 4. DINO：学习“同一个东西的不同 view 应该一致”

### 4.1 训练过程

DINO（Self-Distillation with No Labels）包含结构相同的 student 和 teacher。同一张图像经过不同 crop 和增强后分别送入两个网络，student 学习匹配 teacher 的输出分布。teacher 不通过反向传播更新，而是 student 参数的指数移动平均（EMA）。

$$
\theta_t\leftarrow m\theta_t+(1-m)\theta_s
$$

$$
\mathcal{L}_{\text{DINO}}
=H\left(p_t(x_1),p_s(x_2)\right)
$$

> “虽然 crop、视角和外观变了，但这些 view **仍然应该表示同一个对象**。”

### 4.2 它倾向学到什么？

DINO 的目标是不同 view 之间的一致性，因此倾向忽略增强造成的变化，保留稳定的物体级语义。DINO 训练的 ViT 还会涌现出较强的物体边界和场景布局信息。

### 4.3 优势与限制

- **优势**：强语义表示；对分类、检索、目标中心的任务很有用；不需要人工标签或显式负样本。
- **限制**：性能较依赖数据增强策略；如果某个增强破坏了触觉任务所需的信息，“对增强不变”反而会让模型丢掉关键物理信号。

## 5. I-JEPA：预测“被挡住区域的抽象表示”

### 5.1 训练过程

I-JEPA（Image-based Joint-Embedding Predictive Architecture）也会遮挡图像，但它不要求恢复像素。context encoder 只看可见区域，predictor 根据 context 表示和 target 的位置信息，预测 target encoder 为被遮挡区域产生的 embedding。

$$
\hat{z}_{\text{target}}
=P\left(E_c(x_{\text{context}}),\text{position}_{\text{target}}\right)
$$

$$
\mathcal{L}_{\text{I-JEPA}}
=\left\|\hat{z}_{\text{target}}-\operatorname{sg}\left[E_t(x_{\text{target}})\right]\right\|_1
$$

其中 $\operatorname{sg}$ 表示 stop-gradient（停止梯度）。target encoder 通常通过 context encoder 的 EMA 更新。

> “我不需要知道被挡住区域的每个像素；我要预测它在 representation space 中**应该表示什么**。”

### 5.2 为什么 latent prediction 更抽象？

同一个物体区域可能有许多合理的像素实现，但高层语义可能相同。target encoder 可以将光照、噪声和微小纹理压缩掉，让 predictor 专注于更可预测的高层信息。

### 5.3 优势与限制

- **优势**：避免重建每个像素；强调抽象语义与区域关系；不依赖大量手工 view augmentation。
- **限制**：训练效果依赖 masking 策略、target encoder 和防止 representation collapse（表示坍塌）的机制；被 target representation 丢弃的低层细节可能恰好是某些密集触觉任务所需的。

## 6. V-JEPA：从空间预测走向时空预测

### 6.1 它与 I-JEPA 的关系

V-JEPA（Video Joint-Embedding Predictive Architecture）保留了 JEPA 的核心思想：**在潜在空间预测，而不是在像素空间重建**。不同点是输入从单张图像变成了视频，patch 也变成同时具有空间和时间位置的 token。

```text
I-JEPA：根据图像的可见区域 → 预测其他空间区域
V-JEPA：根据视频的可见时空区域 → 预测其他时空区域
```

### 6.2 它倾向学到什么？

要预测视频中被遮挡的时空 embedding，模型不仅要知道“这是什么”，还要知道“它如何变化”。因此 V-JEPA 能同时学习：

- 物体外观和场景语义；
- 运动方向、速度和动作阶段；
- 跨帧的持续性和状态变化。

### 6.3 优势与限制

- **优势**：将表示学习扩展到动态场景；适合动作识别、运动理解和物理状态建模；不需要文本、人工标签或像素重建。
- **限制**：视频数据和训练计算成本更高；原始 V-JEPA 学的是时空表示，不等于它自动成为了可执行动作规划的 world model（世界模型）。

> [!note] V-JEPA 与 V-JEPA 2 不要混淆
> 原始 V-JEPA 主要验证“仅靠视频特征预测就能学到强表示”。后续 V-JEPA 2 进一步扩展规模，并通过 action-conditioned 后训练用于机器人规划。

## 7. Sparsh：将自监督表示学习系统化地带到触觉领域

### 7.1 Sparsh 要解决的问题

视觉式触觉传感器会将接触造成的形变转换为图像。传统方法往往需要针对每种传感器和每个任务单独收集标签、训练模型。Sparsh 的目标是先用大量无标签触觉数据学一个通用 encoder，再用小型下游头完成具体任务。

$$
\text{unlabeled tactile data}
\xrightarrow{\text{SSL pretraining}}
\text{general tactile encoder}
\xrightarrow{\text{lightweight probe/decoder}}
\text{downstream task}
$$

### 7.2 Sparsh 不是一个单一 loss

Sparsh 比较了多种自监督路线：

- **Sparsh (MAE)**：在触觉图像上做 masked pixel reconstruction；
- **Sparsh (DINO / DINOv2)**：通过 self-distillation 学习对 view 变化稳定的触觉表示；
- **Sparsh (I-JEPA)**：在潜在空间预测被遮挡触觉区域的表示。

论文的一个关键观察是：Sparsh (DINO) 和 Sparsh (I-JEPA) 竞争力最强，说明对于触觉表示，**在 latent space 中学习**可能比精确重建所有像素更能得到可迁移特征。这是该工作范围内的实验结论，不代表 MAE 在所有触觉任务上都更差。

### 7.3 为什么触觉特别需要短时序？

单帧触觉图像能显示当前形变，但许多物理量是由“如何变化”决定的，例如滑动趋势、剪切方向、接触建立和释放。Sparsh 发现，背景扣除与对约 $80\,\text{ms}$ 的小时间窗进行 tokenization（标记化）对通用表示很重要。

> [!tip] 与 V-JEPA 的联系
> Sparsh 使用短时间窗，说明触觉也是动态信号；但这不意味着 Sparsh 就等于 V-JEPA。两者的共同点是都重视时序结构，而原始 Sparsh 家族主要系统比较的是 MAE、DINO/DINOv2 和 I-JEPA 路线。

### 7.4 它倾向学到什么？

Sparsh 希望 encoder 保留的不是某个单一任务的标签，而是多种任务可以共用的接触状态，例如：

- 接触位置与法向；
- 法向力和剪切力场；
- 物体相对位姿；
- 滑动、纹理和操作状态。

## 8. 几组最容易混淆的关系

### 8.1 MAE vs I-JEPA：都遮挡，但预测空间不同

| | MAE | I-JEPA |
|---|---|---|
| 共同点 | 使用可见 context 预测被遮挡区域 | 使用可见 context 预测被遮挡区域 |
| 目标 | 真实像素 | target encoder 产生的 embedding |
| 必须保留 | 能恢复外观细节的信息 | 能预测抽象 target 的信息 |
| 直觉 | “画回来” | “理解那里是什么” |

### 8.2 DINO vs I-JEPA：都有 teacher，但任务不同

| | DINO | I-JEPA |
|---|---|---|
| 学习关系 | 同一样本的不同 view 应一致 | context 应能预测 target region |
| 核心偏好 | invariance（不变性） | predictability（可预测性） |
| 对 augmentation 的依赖 | 较强 | 原始 I-JEPA 不需要手工 view augmentation |
| 直觉 | “换个视角也是它” | “看到局部能推断其他区域” |

### 8.3 I-JEPA vs V-JEPA：核心相同，数据维度不同

| | I-JEPA | V-JEPA |
|---|---|---|
| 数据 | image | video |
| token 结构 | 空间 patch | 时空 token / tubelet |
| 需建模的关系 | 图像区域间的结构 | 空间结构 + 跨帧运动 |
| 适合 | 静态视觉理解 | 动作、运动和状态变化 |

### 8.4 Sparsh vs 其他方法：领域模型 vs 学习目标

```text
MAE / DINO / I-JEPA / V-JEPA
        ↓
定义“无标签时怎么学”

Sparsh
        ↓
研究“怎么在触觉数据上学通用表示”
```

## 9. 如何选择？

| 你更关心的目标 | 更值得优先考虑 | 原因 |
|---|---|---|
| 需要保留微小纹理、变形和密集细节 | MAE 路线 | 像素重建直接约束局部外观 |
| 需要强语义、检索或对 view 变化的鲁棒性 | DINO 路线 | 直接学习跨 view 不变性 |
| 需要区域级抽象语义，不想重建所有像素 | I-JEPA 路线 | 在 representation space 预测 |
| 需要理解动作、运动和时间变化 | V-JEPA 路线 | 直接建模时空上下文 |
| 开发视觉式触觉系统，标签少且希望跨任务迁移 | Sparsh 预训练 encoder | 预训练数据和评估就是面向触觉领域 |

> [!warning] 没有绝对的“最好”
> 一个方法的表示是否好，取决于它在预训练时被迫保留的信息，是否与下游任务真正需要的信息一致。

## 10. 一句话记忆

> [!summary]
> - **MAE**：被挡住的地方“**长什么样**”？
> - **DINO**：这两个 view “**是不是同一个东西**”？
> - **I-JEPA**：被挡住区域的 representation “**应该是什么**”？
> - **V-JEPA**：在这段时空 context 中，被挡住部分“**正在发生什么**”？
> - **Sparsh**：“**怎么用这些 SSL 思想学一个通用触觉 encoder**？”

## 11. 补充：CLIP 不在上述主线中

CLIP 使用成对的图像和文本，通过对比学习将两种模态对齐：

$$
\boxed{\text{image}\leftrightarrow\text{text}}
$$

它主要解决的是 cross-modal alignment（跨模态对齐），而 MAE / DINO / JEPA 主要讨论不使用人工标签时，如何从单一视觉或触觉模态学到表示。

# Self-Attention vs Cross-Attention

## 1. 一句话总览

- **Self-Attention（自注意力）**：同一组 token 内部互相“看”，用于**模态内部建模**。
- **Cross-Attention（交叉注意力）**：一组 token 去“看”另一组 token，用于**模态之间交互**。

> [!summary] 核心区别
> $$
> \boxed{\text{Self-Attention} = \text{模态内部建模}}
> $$
> $$
> \boxed{\text{Cross-Attention} = \text{模态之间交互}}
> $$

## 2. Self-Attention（自注意力）

### 2.1 核心定义

Self-Attention 中，Query、Key 和 Value 都来自**同一个输入序列** $X$：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
$$

$W_Q$、$W_K$、$W_V$ 是三个不同的可学习投影矩阵（projection matrices）。因此，$Q$、$K$、$V$ 的数值通常并不相等，只是它们的**来源相同**。

> [!warning] 常见简写
> $Q=K=V=X$ 只是省略线性投影后的直观写法。严格来说，应写成上面的 $XW_Q$、$XW_K$、$XW_V$。

### 2.2 直觉理解

假设一张图像被切成多个 patch：

```text
[patch 1] [patch 2] [patch 3] [patch 4] ...
```

每一个 patch 都在问：

> “整张图中，哪些其他 patch 对理解我最重要？”

例如，表示机械夹爪的 patch 可以关注物体、接触区域和其他夹爪 patch，因此局部 token 能够直接利用全局信息。

### 2.3 数学形式

标准的 Scaled Dot-Product Attention（缩放点积注意力）为：

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

代入 Self-Attention 的 $Q$、$K$、$V$：

$$
\operatorname{SelfAttn}(X)
=\operatorname{softmax}\left(
\frac{(XW_Q)(XW_K)^T}{\sqrt{d_k}}
\right)XW_V
$$

计算过程可分为三步：

1. $QK^T$：计算每个 Query 与所有 Key 的相关性分数。
2. $\operatorname{softmax}$：将分数归一化为注意力权重（attention weights）。
3. 乘以 $V$：按权重对 Value 加权求和，获得新的 token 表示。

### 2.4 它学到什么？

Self-Attention 主要学习同一组信息内部的依赖关系，例如：

- 空间关系；
- 局部与全局结构；
- 长距离依赖；
- 同一模态内部的语义关系。

例如：

```text
视觉：gripper ↔ object ↔ table
触觉：pressure region ↔ contact boundary ↔ contact shape
```

## 3. Cross-Attention（交叉注意力）

### 3.1 核心定义

Cross-Attention 中，Query 和 Key/Value 来自**不同的信息源**。对于两个模态 $X_A$ 和 $X_B$：

$$
Q=X_AW_Q
$$

$$
K=X_BW_K,\qquad V=X_BW_V
$$

其中，$A$ 是发起查询的模态，$B$ 是被查询的模态。

### 3.2 tactile → vision 示例

设触觉特征为 $z_T$，视觉特征为 $z_V$。当触觉去查询视觉时：

$$
Q=z_TW_Q,\qquad K=z_VW_K,\qquad V=z_VW_V
$$

对应的 Cross-Attention 为：

$$
\operatorname{CrossAttn}(z_T,z_V)
=\operatorname{softmax}\left(
\frac{(z_TW_Q)(z_VW_K)^T}{\sqrt{d_k}}
\right)z_VW_V
$$

直觉上，它表示：

```text
触觉 token：“我这里感觉到了压力变化。”
       ↓ 去视觉 token 中查找
视觉信息：“这个位置是否正在发生接触？”
```

> [!note] 方向很重要
> `tactile → vision` 通常表示 tactile 作为 Query，vision 作为 Key/Value。Cross-Attention 一般不是对称的；`vision → tactile` 会产生另一个结果。

### 3.3 它学到什么？

Cross-Attention 主要学习不同信息源之间的关系，例如：

- 模态对齐（alignment）；
- 信息互补（complementarity）；
- 跨模态对应关系（cross-modal correspondence）；
- 多模态信息融合（multimodal fusion）。

## 4. Self-Attention vs Cross-Attention

| 对比维度 | Self-Attention | Cross-Attention |
|---|---|---|
| Q/K/V 的来源 | 都来自同一输入 | Query 与 Key/Value 来自不同输入 |
| 主要作用 | 建模单个模态的内部关系 | 建模不同模态之间的关系 |
| 主要学习内容 | 结构、语义、长距离依赖 | 对齐、互补、融合 |
| 输出 token 数量 | 通常与输入 $X$ 的 token 数量相同 | 与 Query 的 token 数量相同 |
| 例子 | 图像 patch 之间互相关注 | tactile token 查询 vision token |

## 5. 视觉—触觉模型中的作用

### 5.1 Self-Attention：先建模每个模态内部

```text
RGB patches     → Vision Encoder  中的 Self-Attention
Tactile patches → Tactile Encoder 中的 Self-Attention
```

- Vision Encoder 学习夹爪、物体、背景和接触区域之间的视觉结构。
- Tactile Encoder 学习压力分布、局部形变和接触轮廓之间的触觉结构。

### 5.2 Cross-Attention：再建模模态之间

```text
Tactile features --Query----\
                            Cross-Attention → Tactile-aware visual information
Vision features  --Key/Value/
```

这一过程让触觉 token 根据自己的需要，从视觉 token 中选择最相关的信息，从而实现跨模态对齐与融合。

## 6. 记忆方法

> [!tip] 用“谁在问谁”来判断
> - **Self-Attention**：我问同一组中的其他 token。
> - **Cross-Attention**：我作为 Query，去问另一组 Key/Value token。
> - Attention 输出的 token 数量由 **Query** 的数量决定。
