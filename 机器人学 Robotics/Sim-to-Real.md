# Sim-to-Real（仿真到真实迁移）

在仿真中训练机器人策略，部署到真实机器人。核心矛盾：**仿真和真实世界之间的差距（Domain Gap）会导致仿真的好策略在现实中崩溃**。

---

## 一、Domain Gap 的来源

| 类型 | 仿真 | 真实 | 影响 |
|------|------|------|------|
| **视觉** | 完美渲染的纹理、均匀光照、无运动模糊 | 真实光照、阴影、反光、模糊、镜头畸变 | CNN 过拟合仿真纹理，到真实图像特征错位 |
| **物理** | 简化碰撞（刚性接触、无摩擦不准确）、理想化关节 | 弹性变形、摩擦、backlash（齿轮间隙）、柔性缆线 | 策略学的接触判断和力控参数不适用 |
| **动力学** | 理想化驱动力/力矩模型 | 电机扭矩限制、电流饱和、关节摩擦随温度变化 | 高速动作下误差急剧放大 |
| **传感器** | 完美无噪的 IMU/力传感器/深度图 | 噪声、漂移、丢帧、量程限制、标定偏差 | 基于传感器反馈的控制律失准 |
| **延迟** | 零延迟或恒延迟 | 真实通信延迟 + 计算延迟，且随时间波动 | 高频控制回路相位裕度不够 → 振荡 |

**直觉**：你在 PS5 里学会了骑自行车，不代表能上街骑真的。仿真告诉你一个大概，但"摩擦力"、"风吹的感觉"、"肌肉记忆"只有真实世界有。

---

## 二、为什么不在真实世界直接训练？

| 真实世界训练的问题 | 仿真训练的优势 |
|------|------|
| 时间成本高（真机一天一千步，仿真一秒一万步） | 快（28800x 级加速） |
| 硬件磨损和维修成本 | 零成本试错 |
| 无法并行的物理约束 | 开几百个实例同时练 |
| 危险（真机练抓取 → 撞坏夹爪 / 砸到人） | 撞了重来 |
| Reset 需要人工干预 | Reset 是 GPU 上的一帧渲染 |

**因此 Sim2Real 是必经之路。问题不是"要不要仿真"，而是"怎么让仿真训练的模型在真实世界也能用"。**

## 四、主流方法

### 4.1 Domain Randomization（域随机化）

**核心思想**：不要只在一个仿真环境里训，而是在**成千上万个随机化的仿真世界**里训。如果模型见过足够多的纹理/光照/物理参数变化，到真实世界就像多了一个样本。

| 随机化什么 | 例子 |
|-----------|------|
| **视觉** | 纹理、颜色、光照位置/强度、背景、相机位置微扰 |
| **物理** | 质量、摩擦系数、关节阻尼、执行器增益 |
| **动力学** | 延迟、IMU 噪声/偏置、力传感器噪声 |

**关键**：随机化的分布必须**覆盖**真实世界的参数。分布太窄 → 过拟合，分布太宽 → 学什么都学不好。

**经典案例**：OpenAI 的 Rubik's Cube 手（2019）——在仿真中对灵巧手质量/摩擦/延迟/相机做极端随机化，训完后真手直接拧魔方。

**问题**：Domain randomization 本质是"撒大网"，训练慢、样本效率低。需要精心设计随机化分布。

### 4.2 System Identification（系统辨识，SysID）

**核心思想**：先测出真实世界的物理参数，再把这些参数灌回仿真，让仿真尽量逼近真实。

1. 真实机器人上跑一小段标定轨迹，记录 IMU/编码器/力传感器数据
2. 用优化（梯度下降/CMA-ES）反推出仿真参数（摩擦、质量分布、电机常数）
3. 把优化后的参数设到仿真里，在这个"校准过的仿真"中训练

**问题**：只能校准已知的参数化模型。如果真实世界有仿真模型里根本不存在的行为（如线缆弹性、齿轮间隙），SysID 无能为力。

### 4.3 Domain Adaptation（域自适应）

**核心思想**：不改变仿真环境，而是学一个从 sim 到 real 的映射。让 sim 特征看起来像 real 特征。

| 方法 | 做法 |
|------|------|
| **特征对齐** | 训练时加一个判别器，惩罚"能被区分出 sim 还是 real"的特征 |
| **图像翻译** | 用 CycleGAN/UNIT 把仿真图翻译成真实风格的图，在翻译后的图上训策略 |
| **Student-Teacher** | 教师网络在真实数据（少量）上小训，学生网络在仿真数据上大量训，对齐中间表示 |

### 4.4 Sim2Real with Fine-tuning

**核心思想**：先在仿真训（pretrain），再到真实世界小量 fine-tune。

**关键挑战**：真机数据极度有限（几百条 traj 顶天了），fine-tune 时容易 catastrophic forgetting。解法：加正则、冻结浅层、EMA（指数移动平均）约束权重变化。

### 4.5 Real-World Priors / Hybrid

直接在设计中引入真实世界中应满足的硬约束或强先验：

- **几何约束**：物体不穿透、关节不反拧——仿真里训练也嵌入这些先验
- **动力学先验**：真实接触力矩不可能超过物理极限——动作输出加 clamp
- **高频控制回路**：仿真里也加延迟和噪声，让策略对 high-gain 控制不敏感

## 五、你不知道你不知道的——Unmodeled Effects

这些是高保真建模成本很高、且常被简化或漏掉的 effects；单靠 SysID 往往很难补齐：

| 现象 | 为什么仿真模拟不了 |
|------|------|
| **反射和透明物体** | 深度相机打透明杯子常出现空洞/错误深度；如果仿真传感器模型过于理想，会严重低估问题 |
| **布料和软体** | 真实毛巾的褶皱取决于纤维方向——仿真布料是简化质点弹簧模型 |
| **磨损** | 夹爪用三个月后表面摩擦系数变了；若仿真没有在线更新或随机化这类慢变参数，策略会逐渐失配 |
| **多机器人无线干扰** | 三台机器人同时跑 → ROS_DOMAIN 互相干扰 → 延迟飙到 500ms → 控制器崩掉 |

**这些才是真正导致 Sim2Real 失败的东西。** 解决方法往往不是算法创新，而是工程约束：避开反射（换传感器/加偏振滤镜）、加冗余延迟容限、定期重新标定。

## 六、Sim2Real Gap 评估

部署前先量化 gap，别一上来就炸真机：

| 指标 | 含义 |
|------|------|
| **视觉 gap** | 仿真渲染图 vs 真实相机图的 FID / LPIPS |
| **动力学 gap** | 同样控制输入下仿真和真实的轨迹偏差（仿真先跑一遍 offline，把动作序列给真机跑一遍） |
| **成功率 gap** | 仿真 100% → 真实掉到 10%，但优化 domain rand 后升到 80% |

## 七、选哪种方法？

| 你的情况 | 推荐 |
|---------|------|
| 视觉为主（抓取、操作） | Domain Randomization 视觉参数 + CycleGAN 风格迁移 |
| 接触/力控为主（装配、灵巧手） | SysID 物理参数 + 数据增强（给力传感器读数加噪声） |
| 有少量真机数据（几十条 traj） | Sim pretrain + Real fine-tune + EMA 约束 |
| 动态运动（四足、无人机） | SysID + Domain Rand 质量/惯量 + 实际测试迭代 |

## 推荐阅读

📄 [Domain Randomization for Transferring Deep Neural Networks from Simulation to the Real World](https://arxiv.org/abs/1703.06907) — IROS, 2017 (Tobin et al.)
引入 Domain Randomization 概念的开创性工作。在随机化的仿真图像上训练目标检测器，不经过任何真实数据 fine-tune 即可在真实机器人上工作。

📄 [Solving Rubik's Cube with a Robot Hand](https://arxiv.org/abs/1910.07113) — arXiv, 2019 (OpenAI et al.)
Domain Randomization 的里程碑应用。灵巧手拧魔方，只用仿真训练，通过极端的物理+视觉随机化直接部署到真手。展示了 DR 的上限在哪里。
