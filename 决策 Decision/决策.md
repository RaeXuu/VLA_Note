# 决策（Decision Making）

在不确定性和多个可能动作中，选择最优的行为。规划说的是 *how to go*，决策说的是 *what to do*。

---

## 一、决策在机器人 pipeline 中的位置

```
感知 ──→ 状态估计 ──→ 决策 ──→ 规划 ──→ 控制
                        │
                   这是个分支点：
                   左边有一排书架 → 去哪一排？（决策）
                   选定第二排 → 怎么绕开桌子走过去？（规划）
```

决策解决**战术层面**的问题——选目标、选行为模式、决定优先做哪个任务。

---

## 二、有限状态机（Finite State Machine, FSM）

最经典的决策模型——系统在有限个状态间切换，切换由条件触发。

```
    [IDLE] ──(检测到物体)──→ [APPROACH] ──(距离<0.5m)──→ [GRASP]
      ↑                                                         │
      └────────────────(抓取成功)──────────────────────────────┘
```

**优点**：直观、可审计（每个转换条件可逐条检查）、确定性强。

**问题**：
- 状态数暴增 → 组合爆炸（$n$ 个布尔条件 = $2^n$ 个状态）
- 无法处理不确定性（"物体可能在那"怎么表示？）
- 硬编码，遇到未定义情况直接卡死

**适用**：简单任务、有明确阶段划分的 pipeline。生产环境中大量用 FSM。

---

## 三、行为树（Behavior Tree, BT）

FSM 的升级版——用树形结构组织行为，模块化、可复用。

```
                    Sequence（顺序执行）
                   /        \
        Condition               Fallback（选择执行）
        (有目标?)              /          \
                         Action         Action
                         (捡起来)       (绕过去)
```

### 核心节点类型

| 节点 | 返回值 | 行为 |
|------|:------:|------|
| **Sequence →** | 全部 Success 才 Success | 从左到右依次执行，任一失败则停止 |
| **Fallback ?** | 任一 Success 即 Success | 从左到右尝试，成功就停 |
| **Parallel ⇉** | 指定数量子节点成功即成功 | 同时运行多个子节点 |
| **Decorator** | 修饰单个子节点 | 重试 N 次、限时、反转结果等 |
| **Action** | — | 实际做事的叶子节点 |
| **Condition** | — | 检查条件的叶子节点 |

**为什么机器人工业界喜欢 BT**：
- 比 FSM 模块化——子树可以复用（"抓取子树" 配不同机械臂）
- 可以热切换行为——Fallback 节点让机器人自动降级（先试 A，不行换 B）
- 可视化友好——树形结构一目了然

### 例子：简单操作任务

```
Fallback
├─ Sequence
│  ├─ Condition(obj_in_view?)
│  ├─ Action(approach)
│  └─ Action(grasp)
└─ Action(search)     ← 如果没看到物体，执行搜索行为
```

## 四、MDP（Markov Decision Process）

决策的数学基础——几乎所有 RL 算法都建立在 MDP 上。

### 五元组

$$\text{MDP} = (\mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma)$$

| 元素 | 含义 | 例子 |
|------|------|------|
| $\mathcal{S}$ | 状态空间 | 机器人位姿 + 环境各物体状态 |
| $\mathcal{A}$ | 动作空间 | 前进/左转/右转/停 |
| $\mathcal{P}(s'\|s,a)$ | 状态转移概率 | 执行"前进"，有 80% 概率到前面一格，20% 打滑向左偏 |
| $\mathcal{R}(s,a)$ | 奖励函数 | 到达目标 +100，撞墙 -10 |
| $\gamma \in [0,1)$ | 折扣因子 | 越远的奖励价值越低 |

### 策略与价值

- **策略 $\pi(a|s)$**：在状态 $s$ 下选择动作 $a$ 的（概率）规则
- **价值函数 $V^\pi(s)$**：从状态 $s$ 出发，按策略 $\pi$ 行动的期望累积奖励
- **动作价值 $Q^\pi(s,a)$**：在状态 $s$ 执行动作 $a$ 后，继续按 $\pi$ 的期望累积奖励

$$V^\pi(s) = \mathbb{E}\left[\sum_{t=0}^\infty \gamma^t R(s_t, a_t) \mid s_0 = s, \pi\right]$$

### Bellman 方程（递归定义价值）

$$V^\pi(s) = \sum_{a} \pi(a|s) \left[ R(s,a) + \gamma \sum_{s'} P(s'|s,a) V^\pi(s') \right]$$

**直觉**：当前状态的价值 = 即时奖励 + 折扣后的未来期望价值。Bellman 方程是 DP、Q-Learning 等所有求解方法的根。

### POMDP（Partially Observable MDP）

MDP 假设状态完全可观测（你知道自己在哪、环境全貌）。现实中传感器信息不完整 → POMDP 加入观测模型和信念状态。

POMDP 里维护一个**信念（belief）**——$$b(s)$$ 是各状态的概率分布，在 belief space 上做决策。计算复杂度极高（信念空间是 $|S|-1$ 维连续空间） → 实际中常用近似或退化为 FSM/BT + 确定性策略。

## 五、学习化决策 vs 工程化决策

| | Learned（端到端 RL） | Engineered（FSM/BT+MPC） |
|------|------|------|
| **泛化** | 取决于训练分布；可能泛化到相似新场景，但 OOD 风险高 | 对已覆盖场景可靠；未定义场景需要显式 fallback |
| **确定性** | 不可解释的黑盒 | 每步可审计 |
| **安全问题** | 难保证 | 可加硬约束 |
| **开发成本** | 前期规则少，但数据采集、训练、验证成本高 | 规则设计成本高，但调试路径清晰 |
| **实际落地** | 多用于子模块/局部策略，端到端整机决策仍需安全外壳 | 工业主流 |

**当前趋势**：取两者之长。BT 做高层任务调度 + RL/MCTS 做子行为的策略优化。决策框架不变，只把叶子 Action 换成学习策略。

## 推荐阅读

📄 [Behavior Trees in Robotics and AI: An Introduction](https://arxiv.org/abs/1709.00084) — CRC Press, 2018 (Colledanchise & Ögren)
行为树的权威教材。FSM→BT 的演进动机、节点类型的形式化定义、模块化与可复用性分析。工业界广泛采用的决策框架。

📄 Sutton & Barto. *Reinforcement Learning: An Introduction* — MIT Press, 2nd ed., 2018
RL 的"圣经"。MDP→Bellman 方程→DP→TD 学习→策略梯度的完整推导。第 3-4 章对理解决策问题中的 MDP 形式化特别关键。
