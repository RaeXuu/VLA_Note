# 具身数据

## 一、训练数据来源

三种主要来源：

| 来源 | 特点 | 典型场景 |
|------|------|---------|
| 互联网数据 | 规模大、多样性高，但缺乏具身交互信息 | VLM 预训练、视觉先验 |
| 仿真数据 | 可无限交互、可重置，存在 sim-to-real gap | 强化学习（RL） |
| 真实数据 | 最可靠，但采集成本高、规模受限 | 端到端模仿学习 |

### 方法与数据的匹配关系

- **端到端模仿学习（Imitation Learning）：** 给定图像直接输出动作，需要配对的状态-动作数据，通常依赖真实世界采集。
- **强化学习（RL）：** 需要反复交互试错，依赖仿真环境（真实环境无法承受大量试错成本）。
- **混合策略：** 先在仿真中用 RL 训练 base model，再在真实环境中用模仿学习微调（sim-to-real transfer）。

## 二、人工采集方式

| 采集方式 | 精度 | 便利性 | 代表方案 |
|---------|------|--------|---------|
| 手持夹爪（Handheld Gripper） | 中 | 高（即插即用） | UMI, FastUMI, Pika |
| 遥操作（Teleoperation） | 高 | 中（需主从设备） | ALOHA（主从机械臂） |
| 动作捕捉（Motion Capture） | 较高 | 低（需动捕设备） | DexCap |
| VR 遥操作 | 高 | 中 | iDP3 |

## 三、数据金字塔

![[1769879768149-3.png]]

### 顶层：真实机器人轨迹数据

物理机器人实际采集的轨迹（trajectory）数据。数据量最小，但直接反映真实世界的动力学和交互特性，保证策略的**落地性（embodiment fidelity）**。

### 中层：合成/增强数据

包含两类：
1. **物理仿真合成数据**（synthetic data via physics simulation）— 通过仿真器生成的状态-动作轨迹
2. **神经增强数据**（neurally augmented data）— 利用预训练模型（如视频生成模型）扩展现有轨迹

例如：用视频生成模型为内部遥操作轨迹生成多样化的反事实轨迹（diverse counterfactual robot trajectories），将 88 小时遥操作数据扩充到 827 小时（配以新的语言指令增加多样性）。

### 底层：互联网数据 & 人类视频

- 大规模网络图像-文本数据可预训练 VLM，当 VLM 赋能机器人时，这部分知识间接迁移。
- 带标注或无标注的人类视频提供广泛的视觉和行为先验（visual & behavioral priors）。

![[image-20260201164659002.png]]

### 金字塔的核心逻辑

> 底层提供**广度**（视觉/行为先验），顶层确保**精度**（真实具身落地）。从底到顶，数据量递减、具身真实性递增。

---

## 四、关键概念速查

- **Sim-to-Real Gap：** 仿真环境与真实物理环境之间的分布差异，导致仿真训练的模型直接部署到真实机器人时性能下降。
- **Counterfactual Trajectory（反事实轨迹）：** 对同一条真实轨迹，生成语言指令不同但动作合理的变体轨迹，增强模型泛化能力。
- **Embodiment Fidelity（具身保真度）：** 数据是否包含真实的物理交互信息（接触力、摩擦、惯性等），直接决定策略能否在实际机器人上运行。

## 五、UMI 与 Ego 数据线路对比

两条主流低成本数据采集路线，核心区别在于**是否直接记录机器人可执行的动作**。

### 5.1 UMI 线路（手持夹爪，Handheld Gripper）

**代表工作：** UMI（Stanford, 2024）→ FastUMI（2024）

**核心思路：** 用便携式手持夹爪 + GoPro 相机，人不操作机器人，直接用手抓着夹爪完成任务。夹爪自带摄像头记录 RGB 图像和末端 6-DoF 位姿，无需标定、无需机器人平台。

| 维度 | 说明 |
|------|------|
| 硬件 | 3D 打印夹爪 + GoPro + 鱼眼镜头，成本 ~$400 |
| 数据形式 | RGB 视频 + 末端 6-DoF 位姿 + 夹爪开合状态 |
| 标定 | **无需外参标定**（camera-to-robot），策略直接从图像学习到动作 |
| 策略 | Diffusion Policy（扩散策略），建模多模态动作分布 |
| 泛化 | 同一策略可部署到不同机器人（"Universal" 的含义） |

**优势：**
- 采集极快 —— 人直接用手操作，无需遥操作训练
- 低成本 —— 不需要机器人平台，采集和部署解耦
- 可迁移 —— 同一夹爪在不同场景收集的数据可复用

**局限：**
- 夹爪形态固定，换夹爪需重新适配
- 人手操作与机器人执行存在**动力学层面的 embodiment gap**
- 受限于人手的动作范围和精度

**后续方向：** 向灵巧手 + 手持采集延伸；提升人体工学设计（FastUMI）

---

### 5.2 Ego 线路（第一人称视频，Egocentric）

**代表工作：** Ego4D（2022）→ Ego-Exo4D（2024）→ EgoMimic（2024）→ RISE

**核心思路：** 从**第一人称视角**记录人类操作（头戴相机或眼镜），让机器人学习"人看到的 → 人做的"映射。数据源可以是人类日常活动视频（Ego4D 含 3250 小时数据）或专门的机器人操作采集。

| 维度 | 说明 |
|------|------|
| 视角 | 第一人称（ego view），接近机器人"眼睛"视角 |
| 数据规模 | 可大规模采集 —— 任何人都能戴着头戴相机做任务 |
| 数据形式 | RGB 视频为主，部分含手部姿态、物体交互标注 |
| 机器人关联 | 需要"桥梁"将人类视频转化为机器人可执行的动作 |

**Ego → Robot 的技术路径：**

1. **域适应（EgoMimic）：** 第一人称视频 + 少量机器人配对数据，将人类操作映射到机器人动作
2. **视频生成（RISE 等）：** ego 视频 → 生成机器人视角视频 → 提取动作
3. **3D 手部重建：** ego 视频 → 重建手部 3D 姿态 → retarget（动作重映射）到机器人末端

**优势：**
- 规模化潜力最大 —— 互联网上海量第一人称视频（烹饪、维修、装配...）都是潜在训练数据
- 不绑定特定机器人形态，通用性强
- 记录的是人类自然操作方式

**局限：**
- Embodiment gap 最大 —— 人手 ≠ 机器人夹爪/灵巧手，视角也不完全等同
- 大多数 ego 视频缺乏机器人可执行的动作标注（action label）
- 从视频推测动作的过程引入误差，策略精度受限

---

### 5.3 两条线路对比

| | UMI（手持夹爪） | Ego（第一人称视频） |
|------|------|------|
| **采集硬件** | 专用夹爪 + 相机 | 头戴相机 / 眼镜 |
| **动作精度** | 高（直接记录 6-DoF 位姿） | 低（需后处理提取/推测动作） |
| **采集效率** | 高 | 极高 |
| **可扩展性** | 中（需专用硬件） | 很高（人人可采集） |
| **Embodiment gap** | 中等（手持 vs 机器人） | 大（人手 vs 机器人） |
| **策略表现** | 已可部署真实机器人 | 多数仍在 sim / 简单任务验证 |
| **技术成熟度** | 较高（有完整 pipeline） | 发展中（关键瓶颈未完全解决） |
| **核心挑战** | 硬件形态扩展、跨夹爪泛化 | 从视频中提取精确动作 |

### 5.4 趋势判断

- **UMI 线**在"能用"上走得最快 —— 低成本 + 快速采集 + 直接部署，适合**特定任务快速落地**
- **Ego 线**在"规模"上潜力最大 —— 一旦解决 action extraction / embodiment transfer，可吃掉互联网海量视频红利，适合**通用机器人基础模型**
- 两条路线不互斥，已有工作探索 **ego 视频预训练 + 少量 UMI 式轨迹微调**的组合范式
