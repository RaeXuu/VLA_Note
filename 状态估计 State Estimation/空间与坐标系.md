# 机器人中的空间与坐标系

机器人系统中同时存在多个坐标系（frame），它们之间的变换是所有感知-规划-控制 pipeline 的基础。

---

## 一、常用坐标系一览

```
                    World (世界系)
                       │
                  Base (基座系)
                  /    │    \
              Joint1 Joint2 ...  (关节系)
                  \    │    /
               End-Effector (末端系)
                  │
              Tool/TCP (工具系)
                  │
              Camera (相机系) ── Image (图像系)
                  │
              Object (物体系)
```

### 各坐标系的含义

| 坐标系 | 英文 | 原点位置 | 用途 |
|--------|------|---------|------|
| **世界系** | World / Global / Map | 环境中的一个固定点 | 绝对参考，所有东西最终要对齐到这里 |
| **基座系** | Base | 机器人底座中心 | 机器人的"身体"，所有关节定义以此为根 |
| **关节系** | Joint (Frame) | 每个关节转轴 | 用 DH 参数定义相邻关节之间的变换 |
| **末端系** | End-Effector (EE) | 最后一个关节的末端 | 描述手/夹爪/工具在空间中的位姿 |
| **工具系** | Tool / TCP | 工具尖端（夹爪中心/焊枪头） | 实际与物体接触的点 |
| **相机系** | Camera | 相机光心 | 3D 点到 2D 投影的出发点 |
| **图像系** | Image / Pixel | 图像左上角/中心 | 2D 像素坐标 |
| **物体系** | Object | 物体中心或特征点 | 描述物体的位姿（6D pose） |
| **传感器系** | LiDAR / IMU | 传感器安装位置 | 每个传感器有自己的 frame |

## 二、刚体位姿的数学表示

一个刚体在 3D 空间中的**位姿（pose）** = 位置（position）+ 朝向（orientation），共 6 个自由度（6 DoF）。

### 2.1 齐次变换矩阵（Homogeneous Transformation Matrix）

最常用的表示，一个 $4 \times 4$ 矩阵同时编码旋转和平移：

$$T = \begin{bmatrix} R_{3\times3} & t_{3\times1} \\ 0_{1\times3} & 1 \end{bmatrix} \in \text{SE}(3)$$

- $R$ — 旋转矩阵（$\text{SO}(3)$），正交矩阵，$\det(R) = 1$
- $t$ — 平移向量（$\mathbb{R}^3$）

将点从坐标系 $A$ 变换到 $B$。这里采用 $T_{BA}$ 表示法：右下标是源坐标系，左下标是目标坐标系。

$$\begin{bmatrix} p_B \\ 1 \end{bmatrix} = T_{BA} \begin{bmatrix} p_A \\ 1 \end{bmatrix}$$

### 2.2 旋转的四种表示

| 表示 | 形式 | 参数数 | 优点 | 缺点 |
|------|------|:------:|------|------|
| **旋转矩阵** | $R \in \mathbb{R}^{3 \times 3}$ | 9 | 直接矩阵运算，无歧义 | 冗余参数多，需满足正交约束 |
| **欧拉角** | $(\alpha, \beta, \gamma)$ | 3 | 直观，人类可读 | **万向锁（gimbal lock）**，不唯一 |
| **轴角** | $(\mathbf{k}, \theta)$ | 4 | 几何意义清晰 | 不唯一（$\theta$ vs $-\theta$） |
| **四元数** | $q = w + xi + yj + zk$ | 4 | 无万向锁，插值友好，计算高效 | 不直观 |

**实践选择**：机器人中存储位姿用四元数（稳定、紧凑），显示给人类看时转欧拉角，计算时转旋转矩阵。

### 2.3 欧拉角的方向约定

同一组欧拉角数值，不同约定对应完全不同的朝向。必须明确：

- **旋转顺序**：XYZ? ZYX? ZYZ?
- **参考系**：绕固定轴（extrinsic）还是绕动轴（intrinsic）？

| 领域 | 常见约定 |
|------|---------|
| 航空 | ZYX（yaw-pitch-roll），绕固定世界轴 |
| 机械臂 | ZYZ（欧拉角），绕当前关节轴 |
| ROS | 固定轴 RPY（roll-pitch-yaw），等价于 extrinsic XYZ；很多库也会写成 intrinsic ZYX，需要看 API 文档 |

> 不提约定的欧拉角 = 没有意义

## 三、传感器坐标系的方向约定

不同领域对 $x, y, z$ 轴的正方向有不同定义。搞混了方向 → 机器人往墙上怼。

| 标准 | $x$ 方向 | $y$ 方向 | $z$ 方向 |
|------|:------:|:------:|:------:|
| **ROS (REP 103)** | 前 | 左 | 上 |
| **相机（OpenCV）** | 右 | 下 | 前（光轴方向） |
| **LiDAR（常见）** | 前 | 左 | 上 |
| **NED（无人机）** | 北（North） | 东（East） | 下（Down） |
| **ENU** | 东（East） | 北（North） | 上（Up） |

**ROS 的右手定则**：食指 = x 前，中指 = y 左，拇指 = z 上。

**相机 vs ROS**：相机系 z 朝前（光轴），ROS 系 z 朝上。挂一个相机在机器人上，必须做一次旋转变换，通常用 `static_transform_publisher`。

## 四、TF 树（Transform Tree）

ROS 的核心机制——用一棵**有向树**管理所有坐标系之间的变换关系，自动维护、自动更新、可查询任意两帧之间的变换。

```
map ──→ odom ──→ base_link ──→ camera_link
                    │
                    ├──→ link1 ──→ link2 ──→ ... ──→ gripper
                    │
                    └──→ imu_link
```

- `map → odom` — 定位模块提供（AMCL / SLAM）
- `odom → base_link` — 里程计提供（轮式、视觉、激光）
- `base_link → links` — 机器人模型（URDF）定义，关节角度实时更新
- `base_link → camera_link` — 固定变换（标定得出）

### 关键概念

| 概念 | 含义 |
|------|------|
| **frame_id** | 坐标系名称字符串，如 `"base_link"` |
| **child_frame_id** | 子坐标系 |
| **static transform** | 不会变的变换（如标定好的相机安装位置） |
| **dynamic transform** | 实时的变换（如关节运动、SLAM 更新） |

### 查询 TF

```
# 取 camera 到 base 的变换
rosrun tf tf_echo base_link camera_link

# 代码中
listener.lookupTransform("base_link", "camera_link", ros::Time(0), transform);
```

**TF 的延迟问题**：`lookupTransform` 允许查历史时刻的变换，利用时间戳对齐传感器数据。这是多传感器融合的关键——激光是 $t_1$ 时刻的，相机是 $t_2$ 时刻的，但 TF 树能还原出各自时刻的坐标系关系。

## 五、常见坐标系变换场景

### 5.1 抓取（Grasping）

```
object_pose_in_camera ──→ object_pose_in_base ──→ IK 求解关节角度
      │                            │
  (相机检测物体)            (TF: base→camera变换)
```

### 5.2 导航（Navigation）

```
laser_scan_in_laser_frame ──→ laser_scan_in_odom ──→ laser_scan_in_map
         │                           │
     (原始激光数据)           (TF: odom→laser变换, 再 odom→map)
```

### 5.3 视觉伺服（Visual Servoing）

$$
e(t) = s(t) - s^*
$$

$s(t)$ 是当前图像特征（由相机观测），$s^*$ 是期望特征。误差 $e$ 通过交互矩阵（Jacobian）映射到相机速度，控制机械臂。

### 5.4 外参标定（Extrinsic Calibration）

求 camera 到 base 的固定变换 $T_{\text{base}\leftarrow\text{camera}}$。典型方法：手眼标定（hand-eye calibration），解 $AX = XB$。

这和 [[感知 Perception/相机内外参]] 里的外参是一回事——相机外参即相机系在世界系（或 base 系）中的位姿。

## 六、关键提醒

1. **永远明确坐标系**：说一个点的 $x, y, z$ 时，永远加上"在哪个系下"。$p_{\text{camera}}$ 和 $p_{\text{world}}$ 是两个不同点
2. **欧拉角 = 必须带约定**：不给旋转顺序和参考系的欧拉角没有意义
3. **TF 树上不要有环**：一个子坐标系只能有一个父系。常见错误是同时发布 A→C 和 B→C，导致 C 有两个父系；若 A→B 和 A→C 都存在，本身不冲突，它们只是两个兄弟分支
4. **静态变换优先标定**：不要估一个相机安装位置然后写死在代码里——用标定板 + 手眼标定
